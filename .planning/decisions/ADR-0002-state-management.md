# ADR-0002 — 상태 관리 선택

- **날짜**: 2026-05-12
- **상태**: 확정

## 배경

Flutter 앱에서 지출 내역, 저축 목표, 차트 데이터 등 여러 화면 간 상태를 공유해야 한다.
선택지: Riverpod, Provider, Bloc, GetX

## 결정

**Riverpod** 을 선택한다.

## 대안 검토

| 대안 | 장점 | 단점 | 제외 이유 |
|---|---|---|---|
| Provider | 학습 곡선 낮음 | 보일러플레이트 많음, 업데이트 예정 종료 | 장기 유지보수 불리 |
| Bloc | 엄격한 패턴, 대규모 적합 | 코드량 많음, 오버엔지니어링 | 6주 프로젝트 규모에 과도 |
| GetX | 빠른 개발 | 너무 많은 기능, 안티패턴 유발 가능 | 구조적 학습에 불리 |

## 결정 이유

1. **컴파일 타임 안전성** — 잘못된 Provider 참조를 빌드 시 감지
2. **코드 생성** (`riverpod_generator`) 으로 보일러플레이트 최소화
3. 2024년 기준 Flutter 커뮤니티 **표준으로 자리잡음** → 취업 포트폴리오에 유리
4. 비동기 처리 (`AsyncNotifier`) 가 직관적

## 결과

- `flutter_riverpod`, `riverpod_annotation`, `riverpod_generator` 패키지 추가
- 각 기능별 `*_provider.dart` 파일로 관리
