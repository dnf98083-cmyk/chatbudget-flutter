예상 질문 & 답변

Q. 플랫폼 선택 이유?
Flutter — 단일 코드로 Web·Android 동시 지원. 웹 링크 하나로 발표 데모 가능. ADR-0001 참조.
Q. 앱 구조?
4레이어: Presentation → Domain(파서) → Data(DbHelper) → Infrastructure(SQLite). 파서를 UI와 분리해 독립 테스트 가능.
Q. 개발 환경 설정?
flutter pub get → flutter run 두 줄. docs/setup.md 참조.
Q. 빌드·배포?
flutter build web --release → docs/app/ 복사 → git push → GitHub Pages 자동 서빙.
Q. 테스트?
flutter test — TransactionParser 단위 테스트 3개 (금액·날짜·만원 단위).
Q. API 호출 위치?
외부 AI → AiService (Data Layer). 내부 DB → DbHelper (Data Layer). Presentation은 직접 DB 호출 안 함.

안녕하세요. 저는 챗버짓(ChatBudget)이라는 채팅형 가계부 앱을 개발했습니다.
채팅창에 "스타벅스 6000원" 한 줄만 입력하면 에이아이(AI)가 자동으로 가계부를 기록해주는 플러터(Flutter) 앱입니다.
설치 없이 웹 브라우저에서 바로 실행할 수 있습니다.
이 앱을 만든 이유는 가계부 앱의 가장 큰 문제를 해결하고 싶었기 때문입니다.
기존 앱들은 카테고리를 고르고, 날짜를 설정하고, 금액을 입력하는 과정이 번거로워서 대부분 1~2주 후면 쓰지 않게 됩니다.
챗버짓(ChatBudget)은 "스타벅스 6000원"이라고 채팅창에 한 줄만 치면 에이아이(AI)가 금액·날짜·카테고리를 모두 자동으로 처리합니다.
실제로 이렇게 작동합니다.
"스타벅스 아메리카노 6000"을 입력하면 제미나이(Gemini) 에이아이(AI)가 카테고리는 카페, 금액은 6천원으로 자동 파싱합니다.
"어제 택시 12000원"이라고 하면 날짜도 자동으로 어제로 설정됩니다.
특히 "헬스장 8만원"처럼 기존에 없는 카테고리는 에이아이(AI)가 "헬스장"이라는 새 카테고리를 직접 만들어 저장합니다.
에이아이(AI) 파싱이 실패하면 룰 베이스드(rule-based) 파서로 자동 폴백되어 항상 결과를 받을 수 있습니다.
모스코우(MoSCoW) 우선순위 기법으로 요구사항을 정리했습니다.
머스트(Must)인 채팅 입력, 내역 조회·수정·삭제, 로그인, 통계, 에스큐라이트(SQLite) 저장은 모두 완료했습니다.
슈드(Should)인 저축 목표 관리와 달성 예상일도 구현했고,
쿠드(Could)인 일별 막대 차트, 예산 관리, 에이아이(AI) 카테고리 자동 생성까지 전부 완료했습니다.
앱을 4개 층으로 나눴습니다.
화면을 담당하는 프레젠테이션(Presentation), 자연어 파싱 로직인 도메인(Domain), 디비(DB)와 에이아이(AI) 호출을 담당하는 데이터(Data), 실제 에스큐라이트(SQLite) 파일인 인프라스트럭처(Infrastructure)입니다.
이렇게 나눈 이유는 각 역할을 분리해서 테스트와 유지보수를 쉽게 하기 위해서입니다.
예를 들어 트랜잭션파서(TransactionParser)는 유아이(UI)와 완전히 분리되어 있어서 독립적으로 단위 테스트가 가능합니다.
주요 기술 선택을 에이디알(ADR), 아키텍처 디시전 레코드(Architecture Decision Record) 3건으로 기록했습니다.
플러터(Flutter)를 선택한 이유는 단일 다트(Dart) 코드로 웹(Web)·안드로이드(Android)·아이오에스(iOS)를 동시에 지원하기 때문입니다. 특히 오늘 발표에서 설치 없이 웹 링크 하나로 즉시 데모할 수 있다는 게 큰 장점이었습니다.
상태 관리는 셋스테이트(setState)를 선택했는데, 소규모 앱에 리버팟(Riverpod)이나 블록(Bloc) 같은 외부 패키지를 쓰는 건 과도하다고 판단했습니다.
에스큐라이트(SQLite)는 오프라인 우선 + 개인 금융 데이터를 서버로 보내지 않기 위해 선택했습니다.
이 프로젝트는 클로드 코드(Claude Code) 에이아이 에이전트(AI Agent)와 전 과정을 협업했습니다.
기획서 작성부터 아키텍처 설계, 전체 플러터(Flutter) 코드 구현, 단위 테스트, 배포, 문서화까지 모두 에이아이(AI)와 함께 진행했습니다.
중요한 원칙은 "에이아이(AI)가 만든 것이라도 제가 모두 이해하고 설명할 수 있어야 한다"는 것이었습니다.
