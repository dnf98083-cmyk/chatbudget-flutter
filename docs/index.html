📐 Architecture Decision Records (ADR)
ADR-0001
모바일 프레임워크: Flutter
선택Flutter (Dart)
대안React Native, 네이티브
단일 코드베이스로 Web·Android·iOS·Windows 동시 지원. Hot Reload로 빠른 개발 사이클. Material3 디자인 시스템 내장.
ADR-0002
상태 관리: setState
선택StatefulWidget / setState
대안Riverpod, Provider, Bloc
소규모 앱에서 외부 패키지 없이 이해하기 쉬운 방식 채택. 실시간 갱신은 ValueNotifier로 보완.
ADR-0003
데이터베이스: SQLite
선택sqflite + FFI Web
대안Firebase, Hive, Isar
오프라인 우선. 개인 금융 데이터를 서버로 보내지 않고 기기에 저장. 관계형 구조로 복잡한 쿼리 지원.
🎤 ADR 발표 예상 질문 & 답변
1 Flutter를 선택했는데, React Native 대비 실제로 느낀 장점이 있었나요?
가장 큰 차이는 Web 플랫폼 지원이었습니다. React Native는 웹을 공식 지원하지 않지만, Flutter는 동일 코드로 Chrome에서 바로 실행할 수 있어 데모가 쉬웠습니다. 또한 Hot Reload가 상태를 유지한 채 UI가 즉시 반영되어 개발 속도가 빨랐습니다. 단, Dart 생태계가 npm보다 작아 일부 패키지는 직접 구현해야 했습니다.
2 setState만으로 상태 관리가 충분했나요? Riverpod을 안 쓴 이유는?
화면 수가 4개이고 공유 상태가 "트랜잭션 목록"뿐이라 setState로 충분했습니다. 다만 탭 간 실시간 동기화 문제가 발생해 ValueNotifier를 추가로 도입했습니다. 앱이 커지면 Riverpod으로 마이그레이션할 예정이며, ADR-0002에 그 기준(화면 6개 이상)을 명시해두었습니다.
3 Firebase 같은 클라우드 DB 대신 SQLite를 선택한 이유와 단점은?
개인 금융 데이터의 프라이버시가 가장 큰 이유입니다. 수입·지출 내역을 외부 서버로 전송하지 않고 기기에만 저장합니다. 단점은 기기 간 동기화 불가로, 향후 선택적 CSV 내보내기 기능으로 보완할 계획입니다.
